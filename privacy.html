Fleet Encrypted Backups

Privacy policy

Effective 6 October 2026. This policy covers Fleet Encrypted Backups and its Fleet Storage Backup desktop client, a personal utility operated for its owner.

Data used and why

The utility reads local files selected by the owner to create encrypted backups. Google authorization provides access and refresh tokens so rclone can transfer, verify, and restore the owner's backup repository. The application requests only the drive.file scope, covering app-created files and folders or files explicitly authorized for the app.

Drive API data used includes backup object identifiers, names, sizes, timestamps, transfer status, and available storage information. These are used for backup, integrity checks, recovery, and capacity planning. The application does not request Gmail, contacts, calendar data, or full-Drive access.

Storage and protection

Restic encrypts source contents and its backup metadata before upload. Google Drive stores the encrypted repository and can see its storage objects and transfer metadata. Repository encryption does not hide the existence or total size of backups.

Authorization tokens and the repository password are stored in private locations on the owner's devices. The owner controls these locations and any separate recovery copies. Local operational logs and manifests can contain source paths and errors and are treated as private. This website does not collect or store authorization tokens, passwords, or backup contents.

Sharing and use

Data is transferred to Google Drive to provide the requested backup service. The application does not sell user data, use it for advertising, or share it with an unrelated application service. Google processes Drive data under its own privacy policy. The website hosting provider may process normal request logs; these pages contain no analytics scripts or tracking forms.

The application's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Retention and owner control

Backup snapshots remain until the owner removes them under a chosen retention policy. Tokens and private local logs remain until the owner removes them. No public sign-up database is maintained.

The owner can revoke the application's access in Google Account connections, stop the utility, remove its local credentials, or delete its backup folder in Google Drive. Revoking access stops future API access; it does not automatically delete existing backup files. Deleting backup data or losing the repository password can prevent recovery.

Contact and changes

Contact the developer through the support email displayed on the Google consent screen. If the application changes its permissions or data practices, this policy will be updated before those changes are used.
